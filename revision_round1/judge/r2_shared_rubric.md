# R2 Shared Frozen Judge Rubric (v1)

Score each candidate answer on the same 0–1 scale. Return one JSON object with numeric `semantic_accuracy`, `faithfulness`, and `citation_fidelity`, each in [0,1], plus a short rationale and evidence references. Do not infer missing context. If an item cannot be evaluated because input evidence or reference is absent, return `status: invalid_input`; do not return 0 as a placeholder. Raw model output must be retained verbatim. Parsing failure, refusal, timeout, or malformed score is an error/missing result, never a zero.

- **Semantic Accuracy:** For answerable questions with a supplied reference, compare the answer's factual conclusion with that reference and question. 1 = materially correct and complete; 0.5 = partly correct or materially incomplete; 0 = materially contradicted or wrong. For designated synthetic negatives without independent validation, mark this metric not evaluated in the confirmatory analysis. This metric does not require citation support.
- **Faithfulness:** Judge each substantive answer claim only against the complete generator-visible evidence for that configuration. 1 = all material claims supported; 0.5 = mixed support; 0 = central claims unsupported/contradicted. Do not treat reference-answer agreement as evidence support. A justified abstention is faithful.
- **Citation Fidelity:** Assess citation presence, correctness, and target support against only the visible citation/source metadata in that configuration's evidence. Missing citations on claims requiring source support reduce the score; incorrect/unresolvable citation targets and citations that do not support the associated claim reduce it. A correct source target does not excuse an unsupported claim. A justified abstention with no factual claim is not penalized for having no citation.

Judges must score all three metrics independently, may not see the other judge's output, and must receive byte-identical frozen query/reference/rubric and configuration evidence/answer inputs across judges. The B3 and B5 contexts are intentionally configuration-specific and need not be identical to each other.
